---
title: Role-Based Access Requests for Business Applications
tags: [accounts, security]
---
## Symptoms
- A staff member gets "not authorized" when opening finance, HR, or student records systems.
- A user changed jobs and needs access for their new role, or still has access from their old one.

## Cause
Business systems that hold sensitive data use role-based access. Access must be approved by the data owner, and some roles require completing required training first. Access from a previous role is not removed or added automatically when someone changes jobs.

## Resolution
1. Have the user submit an access request listing the system and the specific role they need.
2. The request goes to the user's manager and then to the system's data owner for approval.
3. Complete any required training, such as student privacy (FERPA) training, before access is granted.
4. Access is usually active within 2 business days of final approval. The user may need to sign out and back in.
5. When a user changes roles, the new manager should request new access and the old manager should request removal of access that is no longer needed.
